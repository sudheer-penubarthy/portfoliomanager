# Upload History Feature Implementation

## Overview
This document outlines the implementation of the Upload History feature for the Portfolio Manager application. The feature allows users to view their previous file uploads with their processing status, record counts, and error details.

## Architecture

### Backend Architecture
The backend follows a clean architecture pattern with the following layers:

```
Controller Layer (UploadHistoryController)
    ↓
Service Layer (UploadHistoryService)
    ↓
Repository Layer (UploadHistoryRepository)
    ↓
Entity/Database Layer (UploadHistory Entity)
```

### Frontend Architecture
The frontend follows Angular best practices:

```
Routes (upload.routes.ts)
    ↓
Component (UploadHistoryComponent)
    ↓
Service (UploadService)
    ↓
HTTP Client → Backend API
```

## Backend Implementation Details

### 1. Entity: UploadHistory
**Location:** `src/main/java/com/sudheer/portfoliotracker/infrastructure/persistence/entity/UploadHistory.java`

**Purpose:** JPA entity representing the upload_history table in the database.

**Key Attributes:**
- `id`: Unique identifier (auto-generated)
- `userId`: Foreign key to portfolio_user (ensures user-specific data)
- `fileName`: Name of the uploaded file
- `uploadDate`: Timestamp of when the file was uploaded
- `status`: Enum (UPLOADED, PROCESSING, COMPLETED, FAILED)
- `recordsProcessed`: Count of successfully processed records
- `recordsFailed`: Count of failed records
- `errorMessage`: Optional error message if status is FAILED

**Database Schema:**
- Table name: `upload_history`
- Indexes created on `user_id` and composite `(user_id, upload_date DESC)` for efficient queries
- Foreign key constraint to `portfolio_user` table with cascade delete

### 2. Enum: UploadStatus
**Location:** `src/main/java/com/sudheer/portfoliotracker/enums/UploadStatus.java`

**Purpose:** Enum to define valid upload statuses.

**Values:**
- `UPLOADED`: File has been uploaded but not yet processed
- `PROCESSING`: File is currently being processed
- `COMPLETED`: File processing completed successfully
- `FAILED`: File processing failed

**Features:**
- JSON serialization/deserialization support
- Case-insensitive value conversion

### 3. DTO: UploadHistoryDto
**Location:** `src/main/java/com/sudheer/portfoliotracker/api/dto/UploadHistoryDto.java`

**Purpose:** Data Transfer Object for API responses (excludes timestamps for cleaner API).

**Key Fields:**
- `id`, `fileName`, `uploadDate`, `status`
- `recordsProcessed`, `recordsFailed`, `errorMessage`

### 4. Repository: UploadHistoryRepository
**Location:** `src/main/java/com/sudheer/portfoliotracker/repository/UploadHistoryRepository.java`

**Purpose:** JPA repository for database operations.

**Key Method:**
```java
List<UploadHistory> findByUserIdOrderByUploadDateDesc(Long userId)
```
- Queries only uploads for a specific user (security)
- Automatically sorts by upload_date in descending order (newest first)
- Generated by Spring Data JPA from the method signature

### 5. Service: UploadHistoryService
**Location:** `src/main/java/com/sudheer/portfoliotracker/service/UploadHistoryService.java`

**Purpose:** Business logic layer for upload history operations.

**Key Method:**
```java
List<UploadHistoryDto> getUploadHistoryForUser(Long userId)
```
- Retrieves upload history from repository
- Converts entities to DTOs
- Logs all operations for debugging

**Security:** 
- No data filtering required as repository query is user-specific
- Service is read-only (transactional=readOnly)

### 6. Controller: UploadHistoryController
**Location:** `src/main/java/com/sudheer/portfoliotracker/api/controller/UploadHistoryController.java`

**Purpose:** REST API endpoint implementation.

**Endpoint:**
```
GET /api/uploads/history
Authorization: Bearer {JWT_TOKEN}
```

**Response:**
```json
[
  {
    "id": 1,
    "fileName": "CAMS_2024_01_15.csv",
    "uploadDate": "2024-01-15T10:30:00",
    "status": "COMPLETED",
    "recordsProcessed": 150,
    "recordsFailed": 0,
    "errorMessage": null
  }
]
```

**Security Implementation:**
1. Extracts JWT token from Authorization header
2. Validates token using JwtTokenService
3. Extracts userId from token claims
4. Returns only that user's upload history
5. No other user's data is accessible

**Error Handling:**
- Returns 400 Bad Request if token is invalid/missing
- Returns 401 Unauthorized if token validation fails

## Database Schema

### upload_history Table
```sql
CREATE TABLE upload_history (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    upload_date TIMESTAMP NOT NULL,
    status VARCHAR(20) NOT NULL,
    records_processed INT NOT NULL DEFAULT 0,
    records_failed INT NOT NULL DEFAULT 0,
    error_message VARCHAR(1000),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    CONSTRAINT fk_upload_history_user FOREIGN KEY (user_id) 
        REFERENCES portfolio_user(id) ON DELETE CASCADE,
    
    INDEX idx_user_id (user_id),
    INDEX idx_user_upload_date (user_id, upload_date DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**Migration:** `V2__Create_Upload_History_Table.sql`

## Security Considerations

### Backend Security
1. **JWT Validation:** Token is validated before processing
2. **User Isolation:** Repository query filters by userId from token
3. **Token Extraction:** userId extracted from JWT claims (not from user input)
4. **No Authorization Bypass:** Service layer doesn't allow filtering by other users

### Frontend Security
1. **Authentication Guard:** Route protected by authGuard
2. **Automatic Token Injection:** JwtInterceptor adds token to requests
3. **Token-based User ID:** Component doesn't manipulate userId (comes from token)

## Integration Points

### How to Use in Existing Upload Flows
When users upload files (in your upload functionality):

1. After successful upload, insert record into `upload_history`:
```java
UploadHistory uploadHistory = UploadHistory.builder()
    .userId(userId)
    .fileName(fileName)
    .uploadDate(LocalDateTime.now())
    .status(UploadStatus.PROCESSING)
    .recordsProcessed(0)
    .recordsFailed(0)
    .build();
uploadHistoryRepository.save(uploadHistory);
```

2. Update status during processing:
```java
uploadHistory.setStatus(UploadStatus.COMPLETED);
uploadHistory.setRecordsProcessed(count);
uploadHistoryRepository.save(uploadHistory);
```

3. On error:
```java
uploadHistory.setStatus(UploadStatus.FAILED);
uploadHistory.setErrorMessage(errorMsg);
uploadHistoryRepository.save(uploadHistory);
```
